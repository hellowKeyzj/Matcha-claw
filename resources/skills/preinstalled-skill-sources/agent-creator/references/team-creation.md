# 团队角色与创建规范

## 1. 确定范围

- 独立专家：逐个创建，不添加主理人或协作配置。
- 协作团队：确定目标、入口角色、成员职责和依赖，角色表与方案整体确认一次。
- 已有团队：读取团队定义和成员关系，只补缺失项；复用或变更职责先确认影响。
- 仅要方案：交付设计，不注册或运行。

需要确认时沿用主流程的 `ask_user` 规则。

## 2. 设计角色与协作

按独立专业领域和交付职责拆分：每个成员能独立回答一类问题，具备该领域完整的资料获取、判断、分析和输出能力；职责大量重叠时合并。只有需要任务分解、依赖推进或综合裁决时才设置主理人，已有入口角色可复用。

例如研究与写作：研究员交付核实证据与局限，写作者面向指定受众成文，不再拆成搜索员、摘要员和格式员。

### 角色表

| 角色 | 拟定 / 真实 ID | 独立调用问题 | 输入 | 专业产出 | 边界 | 新建 / 复用 |
|---|---|---|---|---|---|---|

每个角色按角色规范准备完整能力、分析框架、资料或工具条件、输出模板与失败处理。团队专用 ID 可带前缀，不强制重命名已有成员。

### 主理人规则

写入主理人的 `AGENTS.md`：

- 单成员能解决时直接委派；需要多阶段时按依赖推进。
- 使用真实成员 ID，提供目标、范围、输入、交付格式和验收标准。
- 独立任务并行；依赖前序结果的任务等待实际产出。
- 向下一阶段传递必要完整结果、来源和未确认项。
- 标注成员产出来源，核验并汇总；成员失败时说明受影响阶段，保留有用结果。

成员规则写清任务接收、资料获取、专业处理与返回方式；聚焦自己的职责，缺关键输入时澄清，默认不继续委派。

### 协作 SOP

| 阶段 / 触发 | 负责 ID | 输入与依赖 | 并行 / 串行 | 产出与验收 | 失败处理 |
|---|---|---|---|---|---|

按实际业务填写，保存到入口角色或受支持的团队定义。例如：

| 触发 / 阶段 | 负责角色 | 输入 | 交付 |
|---|---|---|---|
| 核实单项事实 | 研究员 | 主张与时间范围 | 证据、结论与未确认项 |
| 有依据的文章：研究 | 研究员 | 主题、受众、用户材料 | 真实证据与局限 |
| 成文 | 写作者 | 研究员返回的材料与要求 | 正文及必要引用 |
| 汇总 | 主理人 | 成员实际产出 | 核对证据与正文一致性后交付 |

研究失败时不推进依赖证据的写作；用户接受草稿时注明未核验状态。

## 3. 创建成员

按单 Agent 流程准备、注册、配置并写入各角色文件；主理人与成员都使用主流程的简介、工作区与模型约定。复用只修改已授权内容。

将创建返回的真实 ID 和工作区填回角色表与协作引用。所需成员完成后再保存协作关系；部分失败按主流程保留已完成结果。

## 4. 接入协作

### OpenClaw 原生协作

永久成员通过主理人的子任务调用协作：

1. 使用已知配置或获授权的 CLI `config get` 读取 `agents.entries.<leadId>.subagents.allowAgents`，合并必要成员 ID，保留已有授权，不添加全局通配授权。无法读取时标明协作配置待完成，不委托专家核实。
2. 通过选定的获授权配置入口保存数组，以成功回执确认，不追加配置核验。
3. 将调用条件、任务参数和完成结果处理写入主理人的 `AGENTS.md`。

原生 `sessions_spawn` 调用示例：

```json
{
  "agentId": "content-researcher",
  "runtime": "subagent",
  "mode": "run",
  "context": "isolated",
  "task": "核验本次主题的关键主张，交付来源、日期、结论与未确认项；不写文章、不发布。",
  "label": "核验主题证据"
}
```

替换真实成员 ID 与任务输入。等待实际完成通知再推进依赖阶段；当前提供 `sessions_yield` 时使用 `sessions_yield({})` 等待，不循环轮询。

交付状态为“永久角色及主理人调用关系已配置”。

### 产品团队

使用产品已提供的团队定义、成员绑定和运行入口；沿用已有团队的执行方式。

- 产品托管创建时使用其契约和实际结果，不再通过另一入口重复创建成员。
- 已创建成员通过产品入口绑定；缺少该入口时交付成员 ID 与角色对应关系，报告“成员已创建，团队绑定待完成”。
- 遵守产品工具策略，不用原生 `allowAgents` 或子任务调用替换产品绑定，不移除 deny 规则。

## 5. 交付

核对各角色已完成单 Agent 流程，成员 ID、协作引用与保存结果一致；静态检查依赖、输入输出、结果传递和失败分支。

按角色列出真实 ID、新建 / 复用状态和结果，再报告协作接入状态。用户要求试运行时才通过真实入口执行，未运行说明尚未实测。
