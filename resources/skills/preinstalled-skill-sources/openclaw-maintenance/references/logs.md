# 日志取证

用于起不来、秒退、日志空白、只有 failed 标签，或修复后无法判断原错误是否消失。日志优先用 maintenance logs 读取现有脱敏快照；原生诊断 CLI 是补充证据，不为补日志启动 Gateway 或长期 tail/采样。

## 读返回结构，不只摘文本

| 字段 | 判读 |
|---|---|
| `entries` 及每项来源/行 | 区分 lifecycle、Gateway、notice 等实际来源，保留安全的原错误签名；按返回字段解释，不把不同来源混成完整时间线。 |
| `cursor` | 下一次 logs 用返回的非负整数；不用当前时间、行数或自造游标。 |
| `reset` | 游标/源已重置，记录覆盖断点；不把新旧片段当连续证据。 |
| `truncated` | 本次结果不完整；不能用“没看到”证明错误未发生。 |
| `lifecycleTailEvicted` | 早期 lifecycle 尾部已被淘汰；缺失的启动阶段仍未检查。 |

首读不带 cursor；只在本次诊断或授权操作的读回需要时续读。不加任意 limit、路径、过滤命令或 follow 参数，不主动后台订阅。源切换、轮转或重取可能重复记录，重复行不必然表示重复执行。

## 三层证据各有边界

- 应用外围日志解释客户端/Host 交付，不保证包含原生根因。maintenance logs 不是完整 Electron/Host 日志导出器；缺覆盖就报告缺口。
- lifecycle 记录 Gateway/Doctor 输出与准备、停止、修复、启动阶段。即使 Gateway 未 Running，也可能返回保留尾部；不需要先启动才能查启动失败。
- Gateway 日志解释原生运行、插件、渠道与模型错误。只在可取时合并；Gateway 获取失败应保留 notice 和截断标志，不能把空结果当健康。

应用通常补入 state 下的 `logs/openclaw.log`，但已有 logging.file 或 include 时不覆盖；lifecycle journal 是另一来源。不硬编码上游临时目录、不根据示例路径寻找用户 profile。实际路径只在必要私有边界使用，不在报告展示敏感路径。

日志是有界尾部且已脱敏：早期记录可能淘汰、长行可能裁剪、持久化可能失败。落盘失败不证明 Gateway 退出，内存日志存在也不证明持久化成功。对空白结果分别写“没有匹配记录”“覆盖不足”“读取失败”，不混为“无错误”。

## 一次诊断保留什么

1. 用户原动作、故障时间/时区及精确报错；对应本次启动/修复阶段，不拿上一次成功日志验本次。
2. entries 的来源、时间与关键错误 code/cause；截断或脱敏遮住的部分注明未知，不补猜路径、端点或凭据。
3. status 的 lifecycle、repair snapshot、control readiness；日志里打印 listener/PID 不代替这些状态。
4. inspect 的实际构建和目标摘要；同版本号不保证同安装或同数据 shape。
5. 如已执行原生 CLI 诊断，保留命令、退出码、必要 findings 和执行工具的超时/截断/清理状态；不整包展示 stdout/stderr。doctor exit 1 可能是 findings，也可能运行失败，结合 JSON 判读；清理未确认不能写成已回收。
6. 授权变更后保留 receipt/callId，status 查询同次审计，logs 读取本轮新片段。原错误未再出现仅是必要证据，仍须应用内原功能恢复。

敏感字段、URL/路径与凭据可能已被隐藏；隐藏不代表配置中没有它。引用前再次最小化，绝不关闭脱敏、索取 token、复制整份配置/对话、上传 state 或将认证 argv 写入报告。

## 证据不够时

- 明确缺少的时间段、来源或安全错误字段，优先请用户提供应用中可见的脱敏错误，不让其粘贴秘密。
- 提高日志级别会改配置；诊断包/备份会落盘，分享会外发，均不属于现有 logs 读权限。maintenance 没有这些 action，不虚构导出成功或绕用 shell。
- 不为“补日志”盲目重启，不把 debug/trace、模型 probe 或第三方消息作为默认取证前提。达到定位或恢复目的即停止读取。
