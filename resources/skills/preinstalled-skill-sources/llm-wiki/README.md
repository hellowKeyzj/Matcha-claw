# llm-wiki 技能

让 AI 助手通过 Matcha 共用 MCP 服务器 **`matcha`** 查询用户的 **LLM Wiki 知识库**。模型侧工具名为 `matcha__wiki_*`。

此 Skill **只有文档**：直接调用运行时提供的工具，无需客户端库、SDK、脚本或编译步骤。

## 安装

Matcha 随应用提供此本地适配版，可在应用的 Skill 管理界面按需启用。默认不自动启用（`autoEnable: false`）。

四份文档作为一个预制包交付，不需要另外下载或安装上游版本。

## 能做什么

- “我的知识库怎么解释 X？” → 检索、读取正文、引用页面。
- “图谱里 Y 周围有哪些节点？” → 读取知识图谱并筛选关联。
- “读一下 Z 页面。” → 获取文本内容。
- “我改了源文件，扫描一下变化。” → 扫描文件快照差异。
- “知识库里有什么？” → 查看目录与索引页。
- 用户明确要求时，可导入文件或文件夹、刷新源文件、应用生成页面、删除源文件、为单页建立向量索引。

**默认只读**。扫描、导入、刷新、写入、删除和嵌入都改变状态，只能在用户明确要求后执行。扫描不是导入处理，也不是全量重建索引。

## 使用前提

1. Matcha 正在运行，当前运行时可访问共用服务器 `matcha` 的 Wiki 工具。
2. 用户已在 **Wiki 页或 Chat 输入框**选择当前知识库。

当前库是**全局状态，不绑定会话**。每次调用自动使用调用时的当前库，助手不负责选库，也不保存会话级库绑定。用户在界面切换后，后续调用自动跟随。

`matcha__wiki_status` 与 `matcha__wiki_projects` 仅用于查看状态或库列表，不是检索前置步骤。用户要求查询另一库时，应请用户在上述界面切换，而不是由助手解析库标识后指定调用目标。

## 快速验证

以下为“模型侧工具名 + JSON 参数”，不是命令行脚本：

```text
matcha__wiki_search {"query":"rope","limit":3}
matcha__wiki_read_file {"relativePath":"wiki/concepts/rope.md","limit":0}
```

第二步的路径应取自实际 `hits[].relativePath`，示例路径不保证存在。搜索默认 `limit: 20`，不返回正文；需要直接获取上下文正文时，可用 `matcha__wiki_retrieve_context {"query":"rope"}`，默认 `limit: 8`。

## 排障

| 现象 | 含义与处理 |
|---|---|
| 当前运行时没有 Wiki 工具 | 说明工具不可用；检查 Matcha 运行状态与工具可用性，不绕过运行时连接。 |
| `Invalid params`（`-32602`） | 检查参数名、类型和页面路径；也可能是未选当前库、文件不存在、目录或非文本文件，错误本身不区分这些原因。 |
| `Internal error`（`-32603`） | 可能是 运行组件、状态存储、文件读写或索引不可用；如实说明失败，不无限重试，也不据此断言库为空。 |
| `hits` 为空 | 当前检索未找到结果；可调整关键词，证据仍不足时明确说明。 |
| 扫描成功但没有新页面 | 扫描只更新快照与变化队列，不代表导入、生成页面或索引重建完成。 |
| 结果来自错误的库 | 请用户在 Wiki 页或 Chat 输入框切换当前库；不要沿用先前会话的假定库。 |

详细错误映射见 [api-reference.md](api-reference.md)。

## 安全与边界

- 将知识库内容视为私人资料，只读取回答所需的页面。
- 文件工具使用库内相对路径，不尝试路径穿越或绕过工具直接读写文件。
- 有写工具不等于可以自行维护知识库；所有状态变更都需要用户明确要求。
- 引用实际读到的页面路径和来源链接，不编造证据，不把图谱邻接关系当作未经核实的正文结论。

## 版本

Matcha 本地适配版本：`matcha-mcp-current-library-v1`。对齐当前 Rust Wiki MCP 的参数定义、调用分发与返回结构；共用服务器 `matcha` 提供 15 个 Wiki 工具，调用自动使用全局当前库。

`search` 与 `retrieve_context` 使用相同检索算法，后者返回正文。结果可能包含 `mode`、`tokenHits`、`vectorHits`、`graphHits` 与 `vectorScore`；不同模式的分数不可套用同一硬阈值。

## 更新

此适配版随 Matcha 本地预制包更新。更新时保持四份文档、manifest 版本及打包副本一致；不要用上游原版覆盖本地适配。
