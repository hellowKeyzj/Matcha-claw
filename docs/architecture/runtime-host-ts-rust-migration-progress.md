# Runtime Host TS → Rust Migration Progress

> 这是迁移状态账本，不是架构设计文档。没有记录为 `CUTOVER` 的 owner 都不能被宣称为 Rust 唯一 active owner。

## 当前阶段

```text
阶段：Owner implementation and bounded cutover verification
状态：Rust Host active path 持续接线；多个 owner 已到 IMPLEMENTED/VERIFIED，尚无业务 block 达到 CUTOVER
最近更新：2026-09-05
```

当前账本按业务 owner 与横切 owner 记录事实状态。Rust Host 已有 `RuntimeDriver` peer seam、Capability Directory、Runtime Endpoint Directory、Owner actor、private control 与 fixed loopback transports；这些是 active path 证据，不自动构成 owner `CUTOVER`。每个 block 仍必须从真实入口闭合 canonical owner、事实源、Foundation execution、receipt/Unknown/recovery、验证和旧 active path 清理；leaf、producer、fixture 和 focused test 不单独计为完成。

本文件是持久化迁移账本；内部 task list 只用于当前会话的依赖调度和 agent 分派。两者不能互相替代。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `EVIDENCE` | 已完成当前行为/owner 证据整理 |
| `DESIGN` | 目标边界、模型或目录仍在裁决 |
| `IMPLEMENTED` | Rust 有实现，但未证明 active replacement |
| `VERIFIED` | 定向 contract/oracle/package 证据通过 |
| `CUTOVER` | Rust 唯一 active owner，旧 owner 已删除或不可达 |
| `RETIRED` | 产品面已删除，不再迁移为 Rust owner |
| `BLOCKED` | 有明确证据缺口，不得继续猜测 |

## 账本规则

1. 只在实际 source、fixture、fault、package 或 CI 证据后推进状态；
2. `IMPLEMENTED` 不等于 `VERIFIED`，`VERIFIED` 不等于 `CUTOVER`；
3. 没有修改 Renderer/Electron public API 的 unchanged-client 证明，不能 `CUTOVER`；
4. old writer、fallback、dual write、shadow state 未删除/不可达，不能 `CUTOVER`；
5. 任何 `Unknown`、事件丢失、重启、磁盘/权限失败必须有 owner-specific recovery 结论；
6. 每次 cutover 引用独立 technical-gate attestation，不把未来命令当已通过证据。

## 完整闭环门禁

一个 owner/API block 只有以下各项全部成立，才可标记为 `VERIFIED`，并在旧 active path 已退出后标记为 `CUTOVER`：

1. **入口**：实际 delivery/compatibility route 已接入，且有 unchanged-client 或等价外部契约证明；
2. **canonical owner**：状态、策略和副作用归属唯一且已由 Host composition 接线；
3. **事实源**：durable/native facts、desired/persisted/applied/observed 语义明确，不以 projection 或测试 fixture 充当事实源；
4. **Foundation execution**：取消、join、超时和资源清理使用 owner-local `OwnedTask`/`OperationHandle`/`ServiceHandle`，不建立 Host-wide generic operation；
5. **receipt/projection**：成功、拒绝、失败和 `Unknown` 的 public/internal 投影完整，secret、PID、argv、绝对路径和 raw native payload 不泄漏；
6. **失败闭环**：disconnect、timeout、重启、磁盘/权限/进程失败、事件 gap/overflow 等适用故障都有 owner-specific recovery/readback 结论；
7. **验证**：direct contract、fault/oracle、transport、integration、Windows/package（适用时）均通过，不能用单个 leaf test 或 EOF fixture 代替；
8. **旧路径清理**：旧 TS owner、旧 writer、fallback、dual write、shadow state、legacy bridge 已删除或证明不可达。

`producer`、`leaf`、`fixture`、`focused test` 和 `能启动/能连接` 都只是中间证据，不是 owner/API block 完成状态；依赖 producer 完成后，必须继续执行父 owner 的完整闭环，不能自动晋级父 block。
